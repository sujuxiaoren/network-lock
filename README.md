# 网络锁定（Network Lock）

Xiaomi 13 Pro 的 LTE / 5G SA 锁频点、锁小区工具，需要 Root。通过手机自带的 `libdiag.so` 写入基带锁网配置，每次操作前完整备份原配置，可一键恢复。

- 开发者：Liangvv
- 下载：[Releases](https://github.com/sujuxiaoren/network-lock/releases)（APK 与分发包，含使用说明和校验值）
- 使用方法：[0.2.8 使用说明](dist/使用说明-0.2.8.md)

> 只适配已核对固件的 Xiaomi 13 Pro（nuwa）/ Android 13，SIM 1 须为默认数据卡。锁定与恢复会重启基带，双卡网络短暂中断。其他机型或固件请勿使用。

## 0.1.6 的变化

- 增加明确的 LTE 频点模式。该模式不解析或发送 PCI，界面会持久保存模式选择，并使用独立的 lock-earfcn E 后端命令；原有 lock E P 模式保持不变。
- 频点模式按原始 Cellular-Pro 1.9.10[109] 的静态证据写入五项配置：earfcn_lock 使用 legacy FS_WRITE 创建 4 字节普通文件（LE16(E) 加 LE16(E)），cell_restrict_opt_params 使用 36 字节 PUT38（偏移 28 和 32 为 LE32(E)），频段项和 pci_lock 删除。
- 恢复记录升级为 CLREC005（3432 字节），显式区分小区模式和频点模式；CLREC002/003/004 仍按校验后迁移到小区模式。
- 频点模式接受 EARFCN 0–65535。原始函数没有拒绝 0，但当前证据只确认 0 的编码和可逆事务状态，未确认当前固件对频点 0 的实际无线语义。
- 本版本继续使用操作前完整五项快照、外部修改检测、单次重启尝试和自动停止 Cellular-Pro 采集的约束。

0.1.5的已有配置快照和恢复逻辑继续保留：先通过LSTAT、STAT和精确长度GET读取两轮，确认存在性、完整mode、长度和内容稳定，再判断是否可恢复。每次锁定前保存CLREC005完整原始快照，包括原有的全零项和频段项；不会把全零当成不存在。

本版没有保存通用的 Walktour 解锁模板。每次操作前的实际快照是恢复依据；若日后采集 Walktour 清除锁定后的参考基线，也不能替代每次操作前的备份。仅凭五项内容无法断言其他应用的全部清除动作已经复现。

其他 APP 在本次锁定前改过配置，不会仅因此阻止锁频；当前五项须符合下述支持范围、可完整读取且保持稳定，并通过设备和采集检查。恢复会回到本次锁定前的实际状态，其中可能包含其他 APP 原有的锁定；它不是强制通用解锁，也不覆盖五项以外的修改。

## 备份和恢复范围

固定处理以下五个基带路径，不能当作 Android 普通文件路径直接读写：

| 配置路径后缀 | 锁定时的目标状态 |
|---|---|
| modem/lte/rrc/csp/pci_lock | 小区模式：普通文件，4 字节 LE16(EARFCN)＋LE16(PCI)；频点模式：删除 |
| modem/lte/rrc/efs/cell_restrict_opt_params | 特殊 item，36 字节限制结构；小区模式写入 EARFCN/PCI，频点模式写入两个 EARFCN |
| modem/mmode/lte_bandpref | 暂时移除原有频段限制，保存原值供恢复 |
| modem/mmode/lte_bandpref_extn_65_256 | 同上 |
| modem/lte/rrc/csp/earfcn_lock | 频点模式：普通文件，4 字节 LE16(EARFCN)＋LE16(EARFCN)；小区模式删除 |

共同前缀为 /nv/item_files/。范围来自原 APK 已恢复的 LTE 写入及清理流程。

接受不存在项；存在项限完整 mode 为 0160777 的特殊 item，长度为 1–256 字节，其中 pci_lock 必须 4 字节、cell_restrict_opt_params 必须 36 字节。普通文件支持 pci_lock 和 earfcn_lock，长度均为 4、完整 mode 0100001。2026-10-12 的本机频点闭环已通过 STAT/LSTAT 和精确 GET 确认新建 earfcn_lock 的实际完整 mode 为 0100001、长度为 4；每次创建后仍会核实。其他类型、权限或无法完整读取的值会阻止写入。拒绝符号链接及非单链接普通文件，相关父目录必须仍为目录。

锁定前把原始快照同步保存到 /data/adb/lte-cell-lock/lock-recovery-v1.bin，再持久记录每项修改意图。恢复只处理本次记录管理、且仍符合已记录原始/目标/特定中间状态的项；有外部修改、未知部分内容或记录损坏时拒绝猜测。原来不存在的项删除；原来存在的项恢复字节、完整 mode、长度和存在性，再逐项核对。

这是五项锁网配置的恢复，不是整份 EFS 或全基带备份；不承诺恢复时间戳、所有权或其他未读取的系统状态。一般诊断检测也会初始化 DIAG 并切换接收模式，不能描述为完全无状态影响。

每个锁定/恢复阶段均先执行同步准备，再单次请求基带重启。SYNC48 的收据及固定等待不证明异步同步已经完成。超时或进程中断可能导致结果未知，保留记录，不自动重复发送重启。卸载 APK、清除应用数据或删除恢复文件都不等于解除锁定。

## 自动停止 Cellular-Pro 采集

本版核实固定包 make.more.r2d2.cellular_pro 的安装位置、daemon 实际可执行路径、root UID、启动时间及参数中的包名和库路径。验证通过后执行一次应用强行停止，并连续确认 dcidaemon 退出；真正启动 helper 的同一 shell 再检查一次。

此流程会中断 Cellular-Pro 的采集记录，不会自动重启它，也不会盲目终止同名未知进程。该检查不是跨应用的原子互斥，不能排除所有未知诊断工具或检查后竞争。锁定后再次启动采集是否影响限制及邻区显示，需要独立验证。

## 构建与产物

使用本地 SDK 35 / Build Tools 35.0.0、NDK r25c、JDK 17，不使用 Gradle，不自动下载依赖。`build.py` 从仓库上一级目录的 `.analysis/tools` 读取 SDK 与 NDK，路径可在脚本开头修改。

```powershell
python build.py
```

完整构建包含 Java/C 编译、开发证书签名以及签名和 ZIP 对齐检查。仓库不含签名证书：首次构建会在 `.signing/` 生成新的本地开发证书，用它签名的 APK 不能覆盖安装 Releases 中的版本。

- 当前 APK：dist/LteCellLock-0.2.8-experimental.apk（versionCode 18），构建后生成，不随仓库提交；发布包见 Releases。
- 构建信息及 SHA-256：dist/build-info.json（构建后生成）。
- 恢复实现：native/profile.c；有界快照 IO：native/item_probe.c。
- 自动采集协调：app/src/main/java/local/celllock/DiagnosticsCoordinator.java。
